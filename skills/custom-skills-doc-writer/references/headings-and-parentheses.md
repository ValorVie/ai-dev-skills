# 標題與括號

動筆前先讀這一頁。不啟動完整流程的短稿、通知與說明也適用。

## 標題

標題的工作是分類和分階段：讀者只看標題，就知道文件分成哪幾塊、每一塊在整件事的哪個位置。這一節要回答的問題、要讀者做的事和要提醒的話，寫在標題下的第一句，不寫進標題。

- 用短詞組，不寫成句子。名詞或「動詞＋受詞」都可以，例如「事前準備」「切換」「退回方式」。
- 不放指示、條件、提醒、結論、對象或時間。
- 有先後順序的操作用編號加階段名稱，例如「第 1 步：新增驗證紀錄」。
- 同一層標題用同一種寫法，不要有的是名詞、有的是整句。
- 沒有內容的章節不建立。不為了和另一份文件的章節一致，留下一節只寫「這次不用做」；那一句併進相鄰章節，或整節刪掉。

| 不要這樣寫 | 改成 | 原本那句話放哪裡 |
| --- | --- | --- |
| 開始前：請先截圖保存現在的設定，並確認外掛 | 事前準備 | 第一句寫要截圖的畫面與要確認的事 |
| 第 2 步：等通知後改一筆紀錄，完成切換 | 第 2 步：切換 | 第一句寫「收到通知後再做這一步」 |
| 第 0 步：這次不用調整更新時間 | 不建立這一節 | 併成「事前準備」裡的一句 |
| 根因是憑證過期，不是網路問題 | 根因 | 第一句直接寫結論 |
| 給稽核用的變更紀錄 | 變更紀錄 | 第一句寫誰會用到這張表 |

## 括號

括號只用來解釋前一個詞：譯名、白話意思、單位、例子，或畫面上的另一個名稱。例如「TTL（存活時間）」「已代理（橘色雲朵）」。

不用括號替整個標題或整句話標上狀態、對象、影響、用途或寫法。例如「（這次不用做）」「（不會影響網站）」「（給店家）」「（白話版）」。

分辨方法：把括號連同裡面的字刪掉，看少了什麼。

- 少的是前一個詞的解釋：保留括號。
- 少的是對整個標題或整句話的說明：重要的寫成標題下的第一句，不重要的刪掉。

標題的尾巴不掛括號。

## 例外

- 常見問題一節裡，每一題可以用問句。
- 使用者指定的標題、檔名或版本名稱，照使用者的寫法。
- 引用別人的標題、畫面文字或錯誤訊息時照原文。
